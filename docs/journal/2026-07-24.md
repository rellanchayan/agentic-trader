## Lessons for Tomorrow

1. **The tick scheduler must be verified as running before the premarket phase
   completes.** On six consecutive sessions, the premarket phase has executed cleanly
   and then the tick loop has either not run at all or run once, hours late. These two
   phases appear to be scheduled and monitored independently; the premarket succeeding
   does not guarantee the tick loop starts. The Monday morning premarket run should
   include an explicit verification step that confirms `run_phase.sh tick` is scheduled
   and will fire at 9:30 AM ET.

2. **The screener and the plan document must produce one canonical armed-setups list,
   not two diverging ones.** Today, `levels.json` armed INTC and ranked NVDA primary;
   the plan disarmed INTC and ranked NFLX primary. This has now happened on at least
   two consecutive sessions. The tick loop cannot reliably act on a plan that exists only
   in a narrative document — it needs a machine-readable state file that already
   incorporates the premarket reasoning and overrides. The plan narrative is for humans;
   the tick loop needs a single JSON it can trust without arbitration.

3. **Six zero-trade sessions in a row is not a data point; it is a pattern requiring
   a diagnosis before Monday's open.** The cause is not market conditions, not
   setup quality, not risk rules being too tight. The cause is that the tick loop
   consistently fails to run during the entry window. Diagnosing why the scheduler
   stops — or never starts — after the premarket phase should be the first task on
   Monday morning, ahead of any market research.
