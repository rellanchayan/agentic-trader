### Trade 2 — NVDA Flatten SELL (CANCELED — no fill)

| Field | Value |
|---|---|
| Ticker | NVDA |
| Side | SELL |
| Quantity | 44 shares |
| Limit price | $215.22 |
| Submitted | 2026-09-21T20:00:41 UTC (4:00:41 PM ET) |
| Status | CANCELED (all three passes) |

**What happened, step by step:**

1. **Pass 1 (16:00:10 ET):** Flatten script ran. Submitted a DAY LIMIT sell for 44 NVDA at
   $215.22. Alpaca accepted the order and assigned it an order ID. However, this submission
   arrived at or after the 4:00 PM ET market close. Alpaca immediately canceled the order
   because the market session had ended.

2. **Pass 2 (16:00:24 ET):** Flatten script ran again. The idempotency logic checked for an
   existing order ID for NVDA, found the same ID from pass 1, saw its status as CANCELED, and
   treated it as a no-op (already submitted). No new order was created.

3. **Pass 3 (16:00:37 ET):** Same as pass 2. Same order ID, same CANCELED status, same no-op.

The root cause is that the idempotency logic conflates two different states: (a) an order that
is pending/filled (genuinely no-op) and (b) an order that has been canceled (must create a new
order). Case (b) requires a fresh submission, not a no-op. The logic does not distinguish them.

This is the same bug that operated on 2026-09-17, identified in that day's journal.

**Why the flatten ran at 4:00 PM instead of 3:50 PM:** The scheduled passes at 3:50, 3:53, and
3:56 PM ET did not run. The first flatten attempt was at 4:00 PM — too late for a DAY order.
The scheduler mechanism that should trigger the earlier passes remains unrepaired since Sep 17.
