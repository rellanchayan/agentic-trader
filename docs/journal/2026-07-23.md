## Lessons for Tomorrow

1. **A plan written at 9:29 AM and a tick at 2:41 PM are not the same as a functioning
   trading system.** The premarket phase working and the tick loop running once in the
   afternoon produce a good-looking journal with zero trading value. The tick loop must
   run every two minutes from 9:30 AM to 3:58 PM, not appear once after the primary
   entry windows are closed. The scheduler for `bash code/run_phase.sh tick` must be
   verified as operational before market open, independently of the premarket scheduler.

2. **When the screener and the plan document disagree, there needs to be one canonical
   source of truth for the tick loop to read.** Today, levels.json left INTC armed while
   the plan disarmed it. The tick at 2:41 PM used the plan's stance (INTC disarmed).
   That was correct today, but it cannot be a coin-flip decided at 2:41 PM when the
   entry window was 9:45–11:00 AM. The premarket workflow should produce a single,
   reconciled state file that the tick loop reads without ambiguity.

3. **Five consecutive zero-trade sessions means the problem is systemic, not situational.**
   Three of the five days (July 13, 17, 20) had no plan or no tick. One day (July 21)
   had a plan and zero ticks. Today had a plan and one late tick. In no session did the
   system run continuously and then decide to skip trading for legitimate market reasons.
   The "do nothing when the setup isn't there" principle is sound — but it can only be
   applied honestly if the system is actually present and evaluating every two minutes.
   That has not happened on any day this month since July 10.
