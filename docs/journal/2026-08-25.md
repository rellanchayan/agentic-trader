## Plan vs Reality

**CORRECTION to prior journal entry for this date:** The plan WAS written today. `docs/plan/2026-08-25.md`
exists and contains a full, well-formed morning plan. The prior draft of this journal was wrong when it
said the plan was missing for the fourth consecutive session. The root cause is different and more specific.

**What actually happened:** The premarket phase ran successfully this morning and wrote
`docs/plan/2026-08-25.md` to the local clone. However, `code/cloud_sync.sh push` — the step that
commits and pushes changes to origin/main — requires a `GITHUB_TOKEN` environment variable with
`Contents:write` permission. That token was never set in the environment. As a result, the premarket
commit went onto a detached HEAD in the local clone but was never pushed to the remote repository.

Each tick session starts from a fresh clone of origin/main. That fresh clone has no knowledge of the
detached-HEAD commit from premarket. When the 09:40 tick ran, it could not find `docs/plan/2026-08-25.md`
on the filesystem it could see, so it correctly HALTed per the missing-plan playbook rule. From 10:41
onward, the tick sessions (each starting fresh from origin/main) continued to HOLD on their own correct
evaluation of the live market data — the tape simply never cleared the entry gates.

**This is not a trading-logic failure. It is a git sync infrastructure failure.** The premarket phase,
the tick gate logic, and the trading evaluation all worked correctly. The gap is that state written in
one session never reached the next session because the GITHUB_TOKEN sync step was silently dropping every
commit.

## What Didn't Work

**git sync is silently broken.** `code/cloud_sync.sh push` requires `GITHUB_TOKEN` with
`Contents:write` permission. That variable is not set. Every commit from every premarket, tick, and
flatten session since the sync was added has been going onto a detached HEAD in the local clone and
never reaching origin/main. This means:

- Each cloud session starts from origin/main, which is stale.
- Plan files, playbook updates, state changes, and journal entries written by one session are invisible
  to the next.
- The 09:40 tick saw a filesystem without the plan and correctly HALTed — but it HALTed because of
  missing git infrastructure, not because the plan was absent.

This is the actual root cause of the four consecutive "missing plan" journal entries from Aug 20–25.
The premarket phase may have been running successfully on those days too, writing plans to detached
HEADs that were immediately discarded when the next session cloned fresh from origin/main. The prior
journals' diagnosis (premarket scheduler broken) was an incorrect attribution. The trading logic was
correct all along; the inter-session state persistence was broken.

**A human must set `GITHUB_TOKEN` in the environment before the next session.** Until that token is
set and `cloud_sync.sh push` succeeds, every session will be effectively stateless — no plan
persistence, no playbook updates carrying forward, no learning accumulating across sessions.
